# Монетикум — фронтенд

Образовательная quiz-платформа для детей. Дети проходят квизы и выполняют задания, зарабатывая за это виртуальные монеты. Родители (в проекте их называют «Спонсорами») создают задания, управляют бюджетом и следят за аккаунтами детей.

Этот репозиторий — веб-приложение (Next.js), через которое работают три категории пользователей:

- гости — посетители лендинга, демо-квизов и страниц регистрации;
- Спонсоры (родители) — личный кабинет с управлением заданиями, бюджетом и детьми;
- Студенты (дети) — отдельный личный кабинет с квизами, заданиями и копилкой.

Подробное техническое руководство по устройству кода, модулям и тому, как их использовать при разработке, — в файле [`INSTRUCTION.md`](./wiki/INSTRUCTION.md). Этот README — про то, как проект развернуть и запустить.

## Архитектура — коротко

Проект построен по методологии Feature-Sliced Design: код разложен по слоям `app → widgets → features → entities → shared`, где каждый слой может использовать только нижележащие слои, а не наоборот. Это правило проверяется автоматически линтером, а не держится на договорённостях. Подробный разбор — какой слой за что отвечает, где лежит какой код, как писать новый модуль — в [`INSTRUCTION.md`](./wiki/INSTRUCTION.md#архитектура-проекта).

## Требования к окружению

- **Node.js 20 LTS или новее** (Next.js 15 требует минимум Node.js 18.18, но для нового проекта рекомендуется актуальная LTS-версия).
- **npm** (используется как менеджер пакетов — в репозитории лежит `package.json`, отдельного `pnpm-lock.yaml`/`yarn.lock` нет).

Проверить установленную версию Node.js:

```bash
node --version
```

## Установка

Из корня этого репозитория (`frontend/`):

## Переменные окружения

Скопируйте пример конфигурации и заполните своими значениями:

```bash
cp .env.example .env.local
```

Файл `.env.local` не попадает в систему контроля версий — в него кладутся настоящие значения для вашей локальной машины. Ниже — что означает каждая переменная.

| Переменная | Обязательна | Назначение |
|---|---|---|
| `API_URL` | да | Адрес backend API, к которому идут запросы, выполняемые на сервере (Server Components, серверные обработчики маршрутов). Значение из `.env.example` (`https://test.monetikum.ru/api`) указывает на тестовый сервер и подходит для локальной разработки без изменений. |
| `NEXT_PUBLIC_API_URL` | да | Адрес API для запросов из браузера. По умолчанию это внутренний путь `/api/proxy` — реальный адрес backend браузер никогда не видит напрямую, запрос проходит через сам Next.js-сервер (детали — в `wiki/INSTRUCTION.md`). Менять это значение без изменения серверной части не нужно. |
| `AUTH_SECRET` | да | Секретный ключ, которым шифруется сессия пользователя (next-auth). Без него приложение не запустится — авторизация не будет работать. Сгенерировать значение можно командой: |

```bash
npx auth secret
```

Команда сама допишет сгенерированное значение в `.env.local`. Альтернативный способ сгенерировать случайную строку вручную:

```bash
openssl rand -base64 33
```

**Важно:** значение `AUTH_SECRET` держите в секрете и никогда не публикуйте — им шифруется, помимо прочего, пользовательская сессия авторизации на backend.

## Запуск в режиме разработки

```bash
npm run dev
```

Приложение поднимется на [http://localhost:3000](http://localhost:3000). Сервер разработки использует Turbopack (быстрая пересборка при изменении файлов) и перезагружает страницу автоматически при сохранении изменений.

## Сборка и запуск в production-режиме

Собрать оптимизированную production-версию:

```bash
npm run build
```

Запустить собранное приложение (после `npm run build`):

```bash
npm run start
```

## Проверка кода

Перед тем как commit-ить изменения, стоит прогнать все проверки — то же самое делает автоматика при код-ревью.

Проверка типов TypeScript:

```bash
npm run typecheck
```

Линтинг JavaScript/TypeScript-кода:

```bash
npm run lint
```

Автоматическое исправление того, что ESLint умеет чинить сам:

```bash
npm run lint:fix
```

Линтинг SCSS-стилей:

```bash
npm run lint:css
```

## Тестирование

### Модульные и компонентные тесты (Vitest)

Запустить все тесты один раз:

```bash
npm run test
```

Тесты лежат рядом с проверяемым кодом — файлы `*.test.ts`/`*.test.tsx` (например, `src/widgets/Header/header.test.tsx`). Как писать такие тесты для нового компонента — раздел [«Тестирование» в `INSTRUCTION.md`](./wiki/INSTRUCTION.md#тестирование).

### End-to-end тесты (Playwright)

```bash
npm run test:e2e
```

Эта команда сама поднимет сервер разработки (если он ещё не запущен) и прогонит сценарии из папки `e2e/` в настоящем браузере (Chromium). Первый запуск может потребовать установки браузеров Playwright:

```bash
npx playwright install chromium
```

## Структура репозитория (верхний уровень)

```
frontend/
├── src/
│   ├── app/          — страницы и маршруты (Next.js App Router)
│   ├── widgets/       — крупные составные блоки страниц
│   ├── features/       — пользовательские сценарии (пока пусто, появится по мере разработки)
│   ├── entities/       — бизнес-сущности проекта (пока пусто, появится по мере разработки)
│   └── shared/         — переиспользуемый код без бизнес-логики: UI-обёртки, работа с API, конфигурация
├── e2e/                — сквозные тесты (Playwright)
├── wiki/               — подробная документация (см. INSTRUCTION.md)
├── docs/plans/          — планы реализации будущих этапов разработки
├── .env.example         — пример файла с переменными окружения
├── next.config.ts        — конфигурация Next.js
├── eslint.config.mjs      — конфигурация ESLint (включая проверку архитектурных границ)
├── vitest.config.ts       — конфигурация модульных тестов
└── playwright.config.ts    — конфигурация сквозных тестов
```

Подробное описание того, что лежит в каждой папке `src/`, как эти части работают вместе и как добавлять в них новый код — в [`INSTRUCTION.md`](./wiki/INSTRUCTION.md).
